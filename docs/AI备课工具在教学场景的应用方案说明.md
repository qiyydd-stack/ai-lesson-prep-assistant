# AI备课工具在教学场景的应用方案说明

## 一、方案定位

AI备课辅助工具面向中小学教师日常备课场景，帮助教师在输入学科、年级、章节、课时和学情后，快速生成可二次修改的结构化备课初稿。工具不替代教师专业判断，定位为“备课起草助手”和“教学设计启发工具”。

## 二、功能说明

### 1. 基础信息输入

教师填写学科、年级、章节/课题、课时安排和学情补充。学情补充可包含学生基础、班级差异、课堂参与度、特殊学习困难等信息。

### 2. 教学类型切换

系统支持多类教学类型：

- 严谨讲授课：适合概念密集、知识结构要求高的章节。
- 探究启发课：适合数学、科学、语文阅读等需要问题链引导的课堂。
- 考前复习课：适合考点梳理、易错分析、题型归纳和限时训练。
- 一对一家教：适合个性化诊断、薄弱点补救和即时反馈。
- 习题课：适合题目梯度训练、错因分析、变式练习和当堂纠错。
- 实验实践课：适合实验操作、实践探究、观察记录和结果表达。
- 公开展示课：适合公开课、展示课、教研观摩等需要突出课堂亮点的场景。
- 自定义：适合跨学科项目课、低年级活动课、错题讲评课等特殊场景，教师可用自然语言描述课型要求。

### 3. 教学风格切换

教学风格用于控制课堂表达气质、互动方式和推进节奏。系统支持：

- 严谨清晰：适合需要概念准确、层次分明的课堂。
- 启发引导：适合通过问题链和追问推动学生思考的课堂。
- 互动活跃：适合需要提高参与度和课堂反馈密度的课堂。
- 温和陪伴：适合基础薄弱、需要信心支持的学生。
- 高效冲刺：适合短时提分、考点突破和关键题型训练。
- 分层照顾：适合学生基础差异明显的班级。
- 故事化情境：适合低年级、语文阅读、综合活动等需要情境带入的课堂。
- 自定义：教师可描述任意语言气质、课堂节奏或互动偏好。

### 4. AI生成备课内容

系统根据输入信息调用大模型生成 Markdown 格式内容，包括：

- 教学目标：从知识与技能、过程与方法、情感态度价值观三个角度设计。
- 重难点分析：说明重点、难点和突破策略。
- 教案框架：覆盖导入、新授/探究、练习巩固、课堂小结、板书/资源建议。
- 课堂互动问题：提供分层提问和预期学生反应。
- 课后作业题：包含基础题、提升题、实践/探究题和设计意图。

教师还可以在生成前选择教案详略、PPT 页数，以及板书设计、课堂评价、分层作业、课堂练习、易错点分析、核心素养、教学反思等可选标签。自定义标签可用于补充学校或教师个人的特殊生成要求。

### 5. 结果复用

教师可复制生成结果，粘贴到教案模板、校内备课平台、Word 文档或教研材料中继续修改。

### 6. 局部重新生成

教师可针对生成结果中的单个模块重新生成，例如教学目标、重难点分析、教案框架、课堂互动问题或课后作业题。该能力适合在整体教案可用但局部不满意时使用，避免整份内容反复重写。

### 7. 校本模板导入

教师可粘贴学校教案模板，或导入 `.txt`、`.md` 格式的模板文件。系统会优先参照模板中的栏目结构和表达习惯生成内容。Demo 阶段暂不处理 `.docx` 模板的格式保真，正式落地可进一步接入 Word 模板解析。

### 8. 教学PPT生成

教师在生成备课方案后，可继续生成教学 PPT 预览。系统会把教案转化为 8-10 页左右的课堂幻灯片结构，包含页面标题、要点、教师讲解提示和活动建议。教师确认预览后，可下载可编辑的 `.pptx` 文件，用于课堂展示或后续美化。

系统还支持上传 `.pptx` 占位符模板。教师可在学校 PPT 模板中预先放入 `{{deck_title}}`、`{{slide_1_title}}`、`{{slide_1_bullet_1}}`、`{{slide_1_activity}}` 等占位符，导出时系统会替换为生成内容并尽量保留模板原有版式。`.ppt` 属于旧二进制格式，Demo 阶段建议先另存为 `.pptx` 后上传。

## 三、适用场景

### 1. 日常备课

适用于教师快速形成第一版教案框架，减少重复性文本整理时间，把精力更多放在课堂活动取舍和学生差异化支持上。

### 2. 集体备课

教研组可围绕同一章节生成多个教学类型版本，用于比较不同课堂组织方式，辅助形成统一教案或分层教学建议。

### 3. 新教师培养

新教师可通过工具学习完整教案结构，理解教学目标、重难点、课堂问题和作业设计之间的关系。

### 4. 公开课与展示课准备

教师可快速生成互动问题链、课堂活动流程和拓展任务，再结合校本要求进行精修。

### 5. 跨学科主题学习

自定义教学类型适合生成跨学科任务描述、过程安排和成果评价建议。

## 四、落地建议

### 1. 从“辅助起草”开始，而不是直接自动发布

学校落地初期应明确 AI 输出为草稿，必须经过教师审核、修改和确认。系统界面和制度说明都应避免让教师直接把 AI 内容当作最终教案。

### 2. 建立校本提示词与模板

不同学校对教案格式、课时结构、核心素养表述和作业要求不同。建议由教务处或教研组沉淀统一模板，并把模板固化到后端提示词中。

### 3. 接入校本资源库

后续可接入教材目录、课标要求、校本课件、优秀教案和作业库。AI 生成时优先引用校内可信材料，减少泛化和不贴合教材的问题。

### 4. 建立内容审核机制

建议增加敏感内容过滤、事实性检查、版权提醒和教师确认流程。涉及学生数据时，应避免上传可识别个人身份的信息。

### 5. 分阶段推广

第一阶段用于个人备课 Demo 和教研组试用。第二阶段接入学校统一账号和模板。第三阶段与教务系统、资源库、作业平台联动。

### 6. 关注教师工作流

工具应嵌入教师已有流程，例如复制到 Word、导出为校内模板、同步到集体备课平台。不要让教师为了使用 AI 额外维护一套复杂系统。

## 五、运行与部署建议

Demo 版本采用前后端分离：

- 前端：Vue 3 + Vite，负责表单和结果展示。
- 后端：Express，负责代理 OpenAI 兼容接口，并把模型 SSE 增量结果转发为前端可直接读取的文本流；PPTX 导出使用 PptxGenJS 生成可编辑 PowerPoint 文件。
- 配置：Demo 可在页面右上角填写 API Key、Base URL 和模型名，也可通过 `.env` 设置 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL` 作为默认值。

正式部署时建议将后端部署在学校或供应商可控环境中，API Key 只保存在服务端，不暴露给浏览器。页面配置 API Key 仅建议用于本机 Demo 演示。若使用国内大模型网关，可通过 OpenAI 兼容接口替换 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`。

## 六、风险与边界

- AI 可能生成不准确或不符合本校要求的内容，教师必须审核。
- AI 不应处理学生姓名、身份证号、家庭住址等敏感信息。
- 生成内容可能存在版权或教材版本不匹配问题，需要结合教材和校本资源修订。
- 工具应作为教师专业能力的放大器，而不是替代教师备课和教研。
